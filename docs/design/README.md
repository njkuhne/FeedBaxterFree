# Design briefs

One brief per component, written by the Opus director from `docs/ARCHITECTURE.md` before any code for that component is written. A brief fixes: the package's exported API and types, the files to create, the tests to write (by name and what each proves), acceptance criteria, and the spec non-negotiables that apply. Sonnet implements exactly one brief at a time and does not change an interface without going back to the brief's author.
